What is a mechatronic system?

NESA syllabus connection

Key terminology

Mechatronics
The combination of mechanical systems, electronics and computer control to create intelligent machines.
Automation
The use of technology to complete a task with little or no continuous human control.
Robot
A programmable machine that senses its environment and performs physical actions.
Control system
A set of components that manages how a machine behaves by processing inputs and controlling outputs.
Human control
Operation in which a person directly gives commands or makes decisions for a system.
Autonomous control
Operation in which a system uses sensors and programmed rules to make decisions without continuous human input.

Read and understand

Mechatronics combines mechanical structures, electronics, sensors, control systems and programming. A mechatronic product is more than a machine with wires attached. Its parts work together as one system to collect information, make decisions and create a physical response.

Most mechatronic systems can be explained using an input–process–output–feedback model. Inputs are information gathered from sensors or users. The process is the decision made by a controller using programmed instructions. Outputs are actions produced by motors, lights, speakers or other actuators. Feedback occurs when the system measures the result and adjusts its behaviour.

Mechatronic systems may be human-controlled, semi-autonomous or fully autonomous. A remote-controlled vehicle depends on continuous human instructions. A modern car may combine human driving with automated braking. An autonomous robot uses sensors and algorithms to make decisions without direct human control.

In this project, a micro:bit V2 will control a two-wheel sumo robot. The robot must follow a line into the arena, detect the ring boundary, locate an opponent and control its motors so it remains inside the ring while attempting to push the other robot out.

Key terminology

Microcontroller
A compact programmable computer contained on a single integrated circuit. It reads inputs, follows programmed instructions and controls outputs.
Processor
The part of a computer or microcontroller that executes program instructions, performs calculations and makes logical decisions.
Memory
Electronic storage used to hold program instructions and data. The micro:bit uses memory to store its program and temporary values.
Input
Data or an electrical signal received by a system from a sensor, button or another device.
Output
An action, signal or result produced by a system, such as motor movement, light, sound or transmitted data.
Pin
A physical electrical connection point that allows a microcontroller to receive an input signal or send an output signal.
Digital signal
A signal with separate states, usually represented as 0 and 1, off and on, or false and true.
Analogue signal
A signal that can contain a range of values rather than only an on or off state.
Firmware
Software stored on a device that manages its basic hardware functions and allows other programs to communicate with it.
Motor driver
An electronic interface that receives low-power control signals from a microcontroller and switches the higher current required by motors.
Current
The flow of electrical charge through a circuit. Motors generally require more current than a microcontroller pin can safely provide.
Voltage
The electrical potential difference that pushes current through a circuit.

Read and understand

A microcontroller is a small programmable computer designed to control an electronic or mechatronic system. Unlike a desktop computer, a microcontroller is normally built into a product and performs a focused set of tasks.

Examples of products containing microcontrollers include washing machines, microwave ovens, automatic doors, traffic lights, drones, medical devices, security systems and robots.

The micro:bit V2 acts as the main controller of the sumo robot. It receives electrical signals from sensors, processes those signals using a program and sends control signals to output devices.

The micro:bit therefore performs the decision-making stage of the robot's input–process–output system.

Main features of the micro:bit V2

The micro:bit V2 includes a range of built-in components that allow it to sense, process, display and communicate information.

  • A processor that executes program instructions
  • Memory for storing programs and data
  • A 5-by-5 LED display
  • Buttons A and B
  • Programmable input and output pins
  • An accelerometer that detects movement and orientation
  • A compass or magnetometer that detects magnetic direction
  • A temperature reading from the processor
  • A microphone for detecting sound
  • A speaker for producing sound
  • Radio and Bluetooth communication
  • USB connection for programming and power

The micro:bit as part of the sumo robot

The micro:bit does not work alone. It forms one part of a larger control system.

Sensors detect information about the robot's environment. For example, a tracking sensor may detect the edge of the arena, while an ultrasonic sensor may measure the distance to an opponent.

These readings are received through the micro:bit's pins. The processor then runs the programmed algorithm and decides what the robot should do.

The micro:bit sends low-power control signals to the Motor:bit board. The Motor:bit uses these signals to control the direction and speed of the two DC motors.

Why the motors need a motor driver

The micro:bit's pins are designed to send and receive small electrical signals. They cannot safely provide the amount of current required by a DC motor.

Connecting motors directly to the micro:bit could cause unreliable operation or damage the microcontroller.

A motor driver board acts as an interface between the microcontroller and the motors. It receives the micro:bit's control signals while using a separate motor power supply to provide the required current.

This means the micro:bit makes the decision, but the motor driver performs the electrical switching needed to run the motors.

Digital and analogue input

Some sensors produce a digital signal. A digital reading normally represents one of two states, such as:

  • 0 or 1
  • black or white
  • pressed or not pressed
  • object detected or not detected

Other sensors produce an analogue signal. An analogue signal can represent a range of values, such as brightness, sound level or sensor intensity.

The program must correctly interpret the type of data being received. Incorrect assumptions about the input signal may cause the robot to make unreliable decisions.

Program execution

The micro:bit follows program instructions in a precise order. A typical robot program repeatedly:

  1. reads sensor values
  2. stores the readings in variables
  3. compares the readings with programmed conditions
  4. selects an appropriate action
  5. sends control signals to the motors
  6. repeats the process

This repeated control cycle allows the robot to continually respond to changes in its environment.

Key terminology

Input
Data or an electrical signal received by a system from a sensor, user or another device.
Sensor
An input device that detects a physical condition and converts it into data or an electrical signal.
Process
The calculations, comparisons and decisions performed by a controller using programmed instructions.
Output
An action, signal or result produced by a system, such as movement, light, sound or transmitted information.
Actuator
An output device that converts electrical energy or a control signal into physical movement or another action.
Storage
The retention of program instructions or data so that they can be used later by the system.
Transmission
The movement of data or electrical signals between components within a system.
Signal
An electrical or digital value used to carry information between components.
Digital input
An input with separate states, usually represented as 0 or 1, off or on, or false or true.
Analogue input
An input that can contain a range of values representing a changing physical condition.
Feedback
Information about the result of a system’s output that is used to adjust its next action.
Feedback loop
A repeated cycle in which a system senses conditions, processes the data, produces an output and then senses the result again.

Read and understand

Mechatronic systems collect information, make decisions and produce physical actions. This can be represented using an input–process–output, or IPO, model.

The IPO model helps designers understand how information moves through a system. It can also help programmers identify which sensors must be read, which decisions must be made and which outputs must be controlled.

Inputs

Inputs provide the system with information. They may come from a user, a sensor or another computer system.

In the sumo robot, the main inputs include:

  • tracking sensors that detect the colour or reflectivity of the surface
  • an ultrasonic sensor that measures the distance to an object
  • buttons used to start, stop or test the robot
  • stored settings such as motor speed and distance thresholds

Sensors do not directly decide what the robot should do. They provide readings that the micro:bit program must interpret.

Processes

Processing occurs when the micro:bit runs the programmed algorithm. The processor may store values in variables, compare readings with thresholds and select an action.

For example, the tracking sensor may return a value representing a black or white surface. The program compares this value with a condition and decides whether the robot should continue forward, reverse or turn.

Processing can include:

  • reading a sensor value
  • storing the value in a variable
  • comparing the value with a threshold
  • checking more than one condition
  • selecting an appropriate behaviour
  • calculating motor speed or direction

Outputs

Outputs are the actions or information produced by the system. In the sumo robot, the most important outputs are the control signals sent to the Motor:bit board.

The Motor:bit then controls the direction and speed of the two DC motors. The motors are actuators because they convert electrical energy into movement.

Other possible outputs include:

  • images displayed on the micro:bit LED matrix
  • sounds from the micro:bit speaker
  • diagnostic information sent through the serial connection
  • radio messages sent to another micro:bit

Storage and transmission

The syllabus model also includes storage and transmission. Storage occurs when the micro:bit keeps program instructions, variables or settings in memory.

For example, the program may store:

  • the current distance reading
  • whether an edge has been detected
  • the current operating mode
  • the selected motor speeds
  • threshold values used to interpret sensors

Transmission occurs whenever data or control signals move between components. A sensor transmits a reading to the micro:bit, and the micro:bit transmits control signals to the Motor:bit board.

Feedback systems

A simple system may produce one output and then stop. An autonomous robot must continually sense and respond to changing conditions.

This repeated process is called a feedback loop. After the robot moves, its sensors collect new information. The program processes the new readings and adjusts the next motor command.

Without feedback, the robot would continue performing the same action even when the environment changed.

For example, a robot programmed to move forward without checking its tracking sensors would eventually drive outside the sumo ring. Feedback allows the system to detect the boundary and change direction.

Key terminology

Iteration
The repeated execution of a set of instructions.
Loop
A programming structure that repeats instructions while a condition is met or for a set number of times.
Condition-controlled loop
A loop that continues according to whether a Boolean condition is True or False.
Count-controlled loop
A loop that repeats a known number of times.
Polling
Repeatedly checking an input or condition to detect a change.
Delay
A programmed pause before the next instruction is executed.

Read and understand

Iteration repeats instructions. A robot control program normally uses a continuous loop to poll sensors, make decisions and update motor outputs.

Delays can make movement predictable, but long delays reduce responsiveness because the robot cannot check sensors while it is sleeping. Short loops usually produce safer autonomous behaviour.

Count-controlled loops are useful for calibration tests, while condition-controlled loops are useful for waiting until a sensor changes.
